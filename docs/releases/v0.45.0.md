# Kagi 0.45.0 — a more Mac-like workspace, compact layouts, and safer Git operations

2026-10-16

This release brings a broad Apple HIG-inspired interface refresh, a compact Graph
workspace, more complete keyboard access, and important data-integrity fixes.
Existing repository drafts and selections remain shared across compact and wide
presentations rather than becoming separate workflows.

## Apple-style interface and window behaviour

- Apple Light and Dark gain quieter chrome, neutral document tabs and separators,
  clearer text contrast, Finder-scale file lists, and improved active/inactive
  selection. Choose **Icon Only** or **Icon and Text** for the toolbar; commands
  that do not fit remain available in its keyboard-accessible **»** menu.
- macOS Settings opens in one separate, non-modal window with grouped preferences,
  live changes and restored geometry. Repository windows remember their display
  and position; Settings fits its display, and UI zoom now reaches **200%**.
- Native menus show the current theme, language, toolbar and workspace selections.
  **Open Recent** and Dock repository entries reopen recent work, and repository
  folders dropped from Finder onto a window or Dock icon use the normal opening
  flow. Removing a Home recent entry removes only its history entry, not files.

## Compact layout without losing your draft

- Below **1000 logical points** wide, Graph replaces its inline navigator with an
  icon rail and anchored section popovers. The supported repository-window minimum
  is **940 × 660 logical points**.
- The compact **Changes** bottom panel shows staged/unstaged files for WIP, or
  commit metadata and changed files for historical selections. Selecting a commit
  reveals its Changes view; selecting a file opens the central diff.
- WIP's **Commit…** action or **⌘Return** opens the existing composer in a pinned
  popover. Draft text, co-authors, file selection and staging survive resizing
  between compact and wide layouts. Toolbars, panes and long tabs fit narrow or
  enlarged interfaces without replacing saved desktop width preferences.

## Motion and system accessibility preferences

- Selection washes, small row arrivals/removals and existing disclosures animate
  across Graph, Navigator, Editor, Changes and Inspector. Pointer actions follow
  visibly moving rows; presentation-only exit rows cannot trigger covered actions.
- macOS **Reduce Motion** is observed at startup and when the system preference
  changes. Either system or Kagi opt-in settles decorative transitions immediately;
  large list changes also settle rather than animating an unbounded batch.
- **Reduce Transparency** provides an opaque alternative for dark PR tiles.
  Notifications now stay bottom-left above the status bar, with a bounded,
  upward-expanding history disclosure; errors remain until explicitly dismissed.

## Keyboard, accessibility and clearer guidance

- Graph, file lists, PR dashboards/swimlanes, Issues, recent repositories, Operation
  Log and inspection lists gain consistent keyboard focus and row navigation.
  Named buttons and selected tab groups improve access to diff hunks, conflict
  adoption, blame, composer tools, Settings, Activity and Analyze.
- Destructive confirmations make **Cancel** the default Return action and keep
  focus inside the dialog. **Command-Period** follows child-first Escape handling;
  sidebar search clears its query before returning focus to the list.
- Shortcut help uses platform-aware notation. English/Japanese guidance explains
  actions and recovery steps instead of internal stages, while complete Git
  diagnostics remain available in Operation Log. Explicit Japanese font fallback
  also covers terminal text and detached tooltips/cards.

## PR, Issue and diff responsiveness

- PR lists use cursor pagination, retain loaded rows and retry state, and preserve
  browsing position during automatic refresh. Adaptive PR detail prioritizes the
  reader at narrow widths while retaining drafts and selected content.
- Unchanged GitHub Markdown preparation is reused, Issue conversations use a
  virtualized variable-height reader, and Editor history retains immutable
  snapshots. These reduce repeated preparation/copying; no speed multiplier or
  CPU/FPS improvement is claimed.
- Large diffs retain measured geometry and reading anchors across unchanged
  reloads, recolouring and reflow, with reliable true-tail scrolling. Image bytes
  are prepared off-thread. WIP opens before expensive status/provider reads, and
  batch Stage/Unstage publishes status without waiting for watcher debounce.

## Safety and data integrity

- Kagi's Quit, Close Window, window-close button and update restart protect unsaved
  Editor buffers across repository/file tabs with **Save All / Discard / Cancel**.
  Failed saves keep the window open; a cancelled update restart remains available
  without reinstalling, and background installation does not replace another dialog.
- Discard preserves literal paths, symlink target bytes and executable modes, and
  fixes a file-to-symlink restoration bug that could overwrite an external target.
  Stage handles dangling symlinks; Unstage changes only approved literal paths.
- Commit and hunk approvals reject changed content. Commit/Amend respect configured
  hooks, signing and effective Git identity. Pull fetches before declaring a branch
  up to date and rejects changed upstream identity before auto-stashing. Tag push
  freezes its destinations and tag object; multi-commit cherry-pick abort restores
  the recorded starting point when rollback is safe.
- Approval cards disclose more of the actual scope: changed files, stash contents,
  rebase candidates and same-head PR merge details. Unsupported external-filter
  writes and unsafe special-repository Sync operations are refused before writing.

## Known limitations and release scope

- Linux tar downloads now use only `kagi-0.45.0-<arch>-linux.tar.gz`; the
  platform-less aliases shipped for the v0.44.0 transition are retired. macOS
  installer tar/DMG, Windows zip, Linux AppImage and Debian packages remain.

- **Dock Quit, logout and shutdown are not covered by the unsaved-buffer veto.**
  They still need an upstream GPUI application-termination admission API (#1614).
  Save work before using these OS termination paths.
- The official-upstream migration includes **#1479-S0–S5 preparation**, not the
  **S6 package/API cutover**. The cosmic-text patch is removed, but GPUI and
  component fork pins remain. Existing conversation selection behaviour is not
  replaced by the planned official TextView scope in this release.
- Find/Replace's library-owned internal fields still use English context menus;
  Kagi-rendered text fields follow the selected UI language. Further native Find
  navigation awaits public upstream actions. Notification Status naming does not
  promise automatic VoiceOver live announcements.
- Editor History's read-only snapshot reader currently lacks a line-number gutter
  and horizontal no-wrap scrolling (#1275). CRLF snapshots favour exact clipboard
  line endings over large-file block virtualization. Stash Apply/Pop does not
  restore saved index-only content; the approval card explicitly warns about it.
- While browsing additional Open PR pages, automatic refresh retains the accepted
  list membership; use **Refresh** to reflect new, closed or deleted PRs. This
  release does not add an in-app executor for restoring file-backup records.
