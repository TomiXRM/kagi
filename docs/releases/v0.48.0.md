# Kagi 0.48.0 — Conflict resolution and safer recovery

## Resolve conflicts in a document workspace

Conflict Mode brings whole-file sources and an editable Result together, with per-hunk **Use**, **Both** and **Change** actions. Choose either ordering when using both sides, select individual source lines, and keep manual edits protected until an explicit Reset all. The file list separates **In progress** and **Saved** resolutions without automatically advancing away from the file you just saved.

- Compare **images, PDFs, binary files, symlinks and submodules side by side** and choose the side to stage. PDF conflicts start with synchronized scrolling; saved submodules show their commit OID. Images share an 8 MiB source budget and report decoding failures explicitly.
- Complete **deleted-on-both-sides and directory/file conflicts in the app**. Confirm the exact affected paths, keep the directory or restore the file at its original path, and remove Git's parked conflict artifact. Recovery references survive even when a later write or verification fails.
- Leave Conflict Mode for **Graph, Pull Requests or Editor**, then use **Back to conflicts** to return to the same Result, file, hunk and scroll position. The in-progress operation remains visible while you are away.
- Find **Abort and Skip in the conflict sidebar header**, beside the operation and step. **Continue sits next to the file actions and Save**, separated from them. With the sidebar hidden, the operation strip retains Abort/Skip; the Repository menu and command palette use the same live availability and confirmation state.
- Resolve files with **CRLF conflict markers**, including zdiff3 base markers, without stripping original source-line endings. Literal marker-looking source text remains content; unresolved or manually pasted markers still block Save.

## Protect repository writes and recover conflict drafts

Repository-wide advisory locking coordinates writes across Kagi windows and processes. A busy repository refuses competing writes without blocking reads, explains the contention, and keeps queued work waiting for admission. Quiet automatic fetches retry later. Unconfirmed commands with live descendants retain protection until their process group is known to have stopped.

Conflict saves and Continue use the approved, frozen resolution rather than rereading mutable working files. External working-tree edits, changed operation steps or changed staging invalidate stale approvals instead of silently overwriting newer work. Git clean filters and executable modes are preserved, including when a resolved `.gitattributes` changes the filtering policy.

Conflict drafts are written atomically by an ordered background writer. Concurrent Kagi processes merge compatible hunk decisions, retain colliding or manual bodies for inspection, and recover verified-corrupt drafts from the last good backup. Damaged drafts without a usable backup are preserved for recovery rather than treated as empty edits.

Failed autosaves surface in the Operation Log and a notification while retaining the live Result. Close, quit and conflict-operation boundaries wait for a durable flush or require the explicit retry/two-step discard flow. Continue, Skip and merge handoff receipts are recorded by the backend worker even if their window closes before completion.

## Quieter feedback and safer confirmation sheets

- **Return does nothing at the root of a destructive confirmation sheet.** Escape or Cmd+. cancels; a deliberately focused button still accepts Space or Return. Destructive captions remain readable in light and dark appearances.
- Conflict and convention statuses use **outline-only labels**, visibly distinct from Stage/Unstage buttons.
- Persistent repository notices stay in the content area, outside the sidebar and Inspector. Notifications belong to the window that owns their subject; Settings, repository windows and standalone Home do not borrow one another's feedback.
- In Conflict Mode, routine feedback uses the fixed-height status footer for four seconds rather than overlaying resolution actions. Persistent notices retain a separate in-flow lane, with compact Skip/Hide/Show controls contained inside the footer.
- Ordinary Git results stay in the footer; background or long-running results use bounded notifications, with complete failure details in the Operation Log. Pull's preparatory steps no longer announce redundant results.

## Steadier branch creation and sidebar navigation

Create branch and Create worktree keep untouched name fields quiet. Editing or Return reveals localized guidance beside the field, and Return on an empty name does not create an operation failure notification or log entry. Preview and error-row space remain stable while typing, without allowing a stale plan to enable Create. Reopening Create branch no longer revives a cancelled name.

A single titlebar **sidebar toggle** and **Cmd+B** control the shell sidebar in Graph, Pull Requests and Issues with the same slide animation. The conflict file sidebar uses the same width reveal and returns focus safely to its toggle when closed. Reduce Motion skips both transitions.

## Known limitations

- **Binary/image and symlink conflict Save stages the chosen side but leaves the working-tree file unchanged**; submodule choices likewise stage the selected gitlink rather than updating its checkout. After Continue/commit, the working tree can therefore still show an unstaged difference from the chosen version. This remains tracked in [#1810](https://github.com/TomiXRM/kagi/issues/1810).
- Background draft queue acceptance is **not a durability acknowledgment**. Abrupt exit, slow or failing storage, or shutdown beyond the available flush budget can still lose an unacknowledged edit. Preserved incompatible or colliding drafts may be inspection-only rather than automatically reapplied.
- PDF comparison displays both documents; it does **not** compute or highlight their differences. Complex uncached pages can still require initial rendering time. Password entry and universal font fidelity are not supported; malformed and password-protected documents show errors.
- Repository advisory locks coordinate Kagi writers, not arbitrary external Git tools. Fresh preflight checks refuse detected external changes; approvals do not freeze global Git configuration, hooks or every external dependency.

## Downloads and platform notes

- **macOS Apple Silicon:** DMG or installer tar. The application is ad-hoc signed, not Developer ID signed or notarized; Gatekeeper may require the documented first-launch steps.
- **Linux x86_64 / aarch64:** tar, AppImage zip and Debian package. Supported host system libraries are still required.
- **Windows x86_64:** zip.
- Platform-specific SHA256SUMS files accompany the packages.

For an isolated version-pinned installation, use the repository's `install.sh` with `--version v0.48.0`; `--prefix` and `--no-modify-path` are supported on macOS/Linux.
