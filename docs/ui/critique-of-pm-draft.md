# #931: PM の Modern UI 基準案への批判

対象: PM が独立に書いた `.claude/worktrees/modern-ui-pm-draft.md`（§/行番号は 2026-10-03 に読んだ版）。これは**採用済みの仕様ではない**。根拠は [固定版 gpui-component・Kagi 調査](research-gpui-component.md) と `origin/main` の調査時点 `e200a6f7` にある Kagi のコード。PM draft 自体は #933 に含まれていないため、以下は問題の文言・値を併記する。統合時は PM draft も版を固定して参照可能にすること。

**結論:** 「同じ役割の部品に同じ基準を持つ」「完成状態を設計する」は正しい。しかし表を *全画面に数値で適用* すると、20px の sidebar、29px の commit graph、modal の安全上の可視領域と Input のズーム/IME が破綻し得る。28px 入力・全 control の focus ring・28px menu・全 animation の reduce-motion は、定数表や固定版 `Theme` の設定だけでは実現しない。**役割別の密度と状態契約を先に決め、満たせない部品は保留**すべき。

**原因の断定にも異議。** 「テキストボックスが古く見える」ことはユーザー観測だが、「gpui-component の Input を既定の見た目のまま放置したのが原因」はまだ仮説。Kagi は既に dark/light・Input の border/caret/ring・選択色を [component theme にマップ](../../crates/kagi-ui-core/src/theme.rs#L1005-L1075)し、PR/Issue filter では [Small Input](../../src/ui/list_filter_strip.rs#L296-L302)を選んでいる。一方、角丸・font_size・focus 外枠の全体規範は未設定。実アプリで同条件の before と修正案を比較せずに、フォント/背景/間隔/入力状態のどれが古さの主因かは判定できない。**採用不足を原因にしないのと同様、token 不足だけを単一原因にしない。**

## (b) 開発ツールの密度・安全な操作モデルとの衝突

1. **「row は 28–36」（§2 L65-70）は Kagi に適用禁止。** 5 ペイン sidebar の一般行は **20px**、worktree 行 24px（[`sidebar.rs:25-35`](../../src/ui/sidebar.rs#L25-L35)）。20→28px は表示行数を **約 29% 減らす**（同じ高さで 20→約14 行）。modal 対象行は 18px・長い一覧は仮想化、graph は lane canvas と **29px** の commit row が位置同期する（[`modal_shell.rs:21-31`](../../src/ui/modal_shell.rs#L21-L31)、[`graph_view.rs:84-104`](../../src/ui/graph_view.rs#L84-L104)）。視覚の統一を理由に row 高を変えるなら `ROW_H`/`uniform_list`/a11y position と画面内件数を**同時**に示す。graph の selected を一律「アクセント背景」にすると ref/branch/差分色の意味も衝突する。
2. **「長文は全件 ellipsis + hover tooltip」（§2 L70）は keyboard/AX の代替でない。** 選択可能な row の名前・状態・順位は [`list_a11y.rs:17-70`](../../src/ui/list_a11y.rs#L17-L70) に載る。tooltip だけでは keyboard のユーザーや読み上げに届かず、長い Git path/hash の識別部分が切れる。幅制約下では name を残し path/port を段階的に省く既存の [`sidebar_worktree_row.rs:582-630`](../../src/ui/sidebar_worktree_row.rs#L582-L630) の規則を保持し、full value は a11y 名・詳細・コピー等で到達可能にする。
3. **「hero search 40px + ⌘K」「substring highlight」「Esc clears then closes」（§2 L50-56）を全検索へ転用しない。** Kagi の PR/Issue inline filter は 180px 幅の Small Input、command palette は `Cmd/Ctrl+P` で起動し、**subsequence fuzzy**（連続した substring とは限らない）で検索し、↑/↓/Enter と単一 Esc close を既に持つ（[`list_filter_strip.rs:296-302`](../../src/ui/list_filter_strip.rs#L296-L302)、[`command_palette.rs:1-13,27-65,345-365`](../../src/ui/command_palette.rs#L345-L365)）。⌘K は現行 shortcut の表示として虚偽で Linux/Windows も無視する。grouping/highlight や二段 Esc は別 UX 変更として検証する。日本語の label に uppercase 見出しを強制しない。
4. **「one primary per surface」「destructive を menu 最下部」（§0 L16-19、§2 L76-84）だけでは Kagi の誤操作を防げない。** メニューは操作の入口で Git write ではなく、plan→confirm→preflight→execute→verify→oplog が書き込みの契約。[`modal_shell.rs:9-12,97-107`](../../src/ui/modal_shell.rs#L9-L12) は対象を隠さず action 行を固定し、`modal_body` は**list と外側を同時に scroll させない**（`:173-199`）。「body scroll、Enter confirms primary」を一律指定すると target/warning/recovery が隠れる・入力中 Enter/IME と競合する。既存の [`modal_key_routing.rs:72-111`](../../src/ui/modal_key_routing.rs#L72-L111) に Enter の共有経路はあるが、安全仕様の証明にはならない。確認の可否と Esc/Enter は modal 種別・focus・IME・Ready/blocked/replan に紐付け、表示された対象と理由が揃って初めて実行。
5. **「error は inline」「error toast は自動消去しない」（§2 L41-46, L91-99）は情報の所有を逆転する。** 入力検証なら field inline は正しい。Git write の詳細は Operation Log に永続化し、toast は**短い bounded preview**（リポジトリ規則）。Kagi の error toast は 8 秒、info は 4 秒、最大 4 個（[`types.rs:113-156`](../../src/ui/types.rs#L113-L156)、[`toast_stack.rs:21-69`](../../src/ui/toast_stack.rs#L21-L69)）。error を全て常駐させると作業面を塞ぎ、ログ障害など明示 ack の場合こそ modal を使う。空 state も「Open Folder…」一択ではなく no repo / zero results / offline / refused / loading を分ける。
6. **「meta 11 / body 13」（§1 L32）も寸法だけで採用しない。** sidebar の補助文字には既に [`SIDEBAR_AUX_TEXT=11`](../../src/ui/sidebar.rs#L37-L40) があり、足りないのは数字の新設ではなく*読みやすさの検証*。最小 zoom 0.7 では 11→7.7px、13→9.1px 相当（`rem` で正しく scale した場合の計算値）。短い age と、Git path・破壊的操作の警告・recovery の文章を同じ「secondary」枠へ落とさない。JA / 丸め / Retina 以外の画面 / Windows font で実際の legibility と省略範囲を確認する。

## (d) 欠落: 基準として採用するために必要な検証と運用

1. **対象と例外の境界がない。** `24/32` は「通常の Input/Button の候補」、sidebar20/worktree24/graph29/modal18 は「維持すべき既存幾何」、command palette は別の surface、と役割を分ける。例外は「何でも特例」ではなく *行と canvas の一致、仮想 list 高、対象可視、操作理由* のように理由と検証項目を併記する。`Theme.radius`/`radius_lg` と Kagi 固有 `rounded`、fixed px、rem、`scaled_px` のどれが各 token の**所有者**か明記する。
2. **見た目の oracle が未定義。** まず Kagi の同じ画面・同じ window 幅/高さ・theme・EN/JA・zoom・状態で **before / 参照 / proposed** を並べ、何を変え何を残すか書く。Pinned story の Default Light は Kagi の baseline ではない。候補は少なくとも狭幅 600/700/750/900、高 zoom 1.25/1.5、light/dark と custom theme（現行 theme 読込含む）、長い path/JA、多数の list 行を検証。色は操作状態ごとに文字/背景コントラストと意味色の判別を示す。既存 [`header_fit.rs:87-138`](../../tests/recovery/header_fit.rs#L87-L138) の bounds test と modal の安全確認は守る。
3. **focus の意味と feedback が空欄。** mouse hover と keyboard focus-visible は異なる。tab 順序・選択・disabled 理由・screen-reader role/name/selected/position/announce を、tab/list/menu/input ごとに定義する。`Role::Tab` を付けただけでは keyboard arrow key は動かない。IME composition の Enter/Esc、Tooltip の keyboard 表示、実際の Click と AX action、重なった overlay の pointer/focus capture を検証。効果を `2px ring` の有無だけで判定しない。
4. **性能・状態遷移を visual の外に追いやっている。** 1000 commit の仮想行を「hover shadow/tooltip/skeleton」で重くしない、graphic lane と row の pixel 同期を崩さない、loading→data/empty→error/blocked の切替で選択と焦点が飛ばない。`prefers-reduced-motion` をうたうなら Kagi の persisted setting と固定版 transition の実際の扱いを画面で観測し、opt-out できない効果を例外扱いにする。
5. **外部参照は名前だけでは基準にならない。** Primer / Linear / Raycast / ChatGPT / macOS HIG / shadcn/Radix（draft L22-23）を混ぜるなら、それぞれ *URL と対象 state の画像/実装、Kagi の置換対象、採らない点* を明記。HIG と web の default spacing をそのまま GPUI/日本語/desktop 密度へ移植しない。新規 UI issue には最小 1 画面の参照と acceptance、Tier A は状態/寸法、Tier B は実画面の**比較と差の理由**を残す。毎 issue に全 token 表をコピーしない。
6. **§3 の因果仮説を事実と混同しない。** H1/H4 は一部支持だが「基準を足せば品質が変わる」「Tier B は描画しか見ない」は未実証/過大。H2 の「agents が component を探さないから手作り」は、既製 Input 21 箇所・自作入力ゼロ・modal241 `div` に自作操作3 という反証に耐えない。H3 の `kagi-ui-core` に定数表を置くだけでは gpui-component の硬直した寸法/状態と Kagi の別の zoom 経路が接続されない。新しい process gate の前に、1–2 画面の具体例と視覚/操作の失敗証拠を先に作る（[調査 §4 仮説](research-gpui-component.md#931-に書かれた-pm-仮説への独立した判定)）。

**統合版への最低条件:** 既存の色/spacing/helper を使った *role 別* token map、採用する実装 API と例外、既存 screen の before/reference/target、各状態の keyboard/AX/安全 contract、theme×JA×zoom×狭幅の確認方法が揃うまで「全 app に適用する規範」と呼ばない。`modern-ui.md` は PM が統合する文書であり、この critique はその前の反証資料に限る。
